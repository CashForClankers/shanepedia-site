Cash for Clankers — GitHub Org

Cash for Clankers is the GitHub organization Shane uses as the umbrella for AI-built businesses, agent infrastructure, and personal operating systems. The name is a Star Wars / sci-fi joke — "clankers" is the slang the clones used for battle droids. The implication: the org is where Shane gets paid for what the robots build. It is not a serious-sounding brand, and that is the point.

Why an org instead of personal repos

Personal-account repos blur the line between hobby code, client work, and durable assets. An org makes the business assets legible:

  • Repos that should outlive any single project live in the org, not under shaneneeley/.
  • Collaborators can be added per-repo without exposing the whole personal account.
  • Public/private split is intentional and visible — outside readers see what is published on purpose, not by accident.
  • If a child project (ElSalKB, OpenCluck, etc.) ever spins out as its own brand or company, the repo can be transferred without rebuilding history.

This is the same logic as [[../topics/agentic-business-studio.md]]: a portfolio of small things, each with its own lane, sharing infrastructure underneath.

Public repos

Public repos are the things Shane actively wants strangers, future collaborators, or potential buyers to find. They function as both proof and shop window.

  • shanepedia-site — the public static-site artifact built from the private Shanepedia wiki. This is the GitHub Pages source for the founder/operator wiki that strangers can browse. The compiled output, not the source. See [[../topics/agentic-business-studio.md]] for how the wiki itself is the product.
  • cobanos-tours — public site code for the Los Cobanos tourism work tied to [[los-cobanos.md]] and [[victor-los-cobanos.md]]. Public because the operator (Victor) and the destination benefit from being indexable.

Anything else that should be public — a SOUL.md template marketplace, an OpenCluck firmware drop, a public OpenClaw skill — would live here too. The default for code that demonstrates a method (rather than a private competitive system) is public.

Private repos

Private repos hold the operating brain: source-of-truth wikis, machine setup, business research that has not been packaged for outside readers, and personality/identity files.

  • shanepedia — the private founder/operator wiki at ~/.openclaw/workspace/projects/shanepedia/. Contains the full raw/sources/, wiki/, and ops layer. The synthesized public artifact ships through shanepedia-site; the corpus stays private because it includes raw photos, contact notes, half-formed bets, and personal calendar context.
  • setup-mac — the 11-phase sequential guide for bootstrapping a secure AI agent dev machine. Private because it is Shane's actual machine setup, not a generic template. If a sanitized version becomes a public template later, that version goes in a separate public repo — not this one.
  • elsalkb — the El Salvador knowledge base lane. One active child of the Shanepedia parent system. Holds trip corpus, photo ingest, operator contacts, and Los Cobanos research that is not ready for public consumption.
  • elsalkb-site — site code for an eventual public ElSalKB output. Private until the public surface is ready to ship.
  • opencluck — firmware, BOM, and operating notes for the chicken coop IoT monitor described in [[opencluck.md]]. Private during the build phase. Likely candidate for public release once a working unit is deployed for 3+ months — the open-hardware story is more useful with proven uptime data attached.
  • openclaw-workspace — the workspace tree for the local OpenClaw gateway: SOUL.md, IDENTITY.md, USER.md, project trees, and skill installs. Private by definition. This is the agent's grounding context. Sharing it would be like publishing a journal.

Public/private split philosophy

The default is private. Things become public when there is a specific reason:

  • A public artifact serves discovery, recruiting, or operator credibility.
  • A repo demonstrates a reusable method that compounds when others adopt it.
  • A site needs GitHub Pages or a public CDN to ship.

Things stay private by default when:

  • The repo contains personal identity context (SOUL.md, USER.md, calendar references).
  • The corpus includes raw photos, contact info, or operator details that were shared in trust.
  • The work is mid-experiment and a public version would be misleading.
  • The competitive edge is the synthesis itself, not the method.

This is more conservative than the typical "build in public" stance. Shane's read: building in public is great for credibility and weak for compounding personal systems. The public face should be a curated artifact (Shanepedia site, working repos), not the raw substrate.

Why "Cash for Clankers"

Beyond the joke: the name signals that Shane is not pretending the org is a serious company. It is a holding place for builds. If something inside it becomes a real business, it gets its own brand. If something inside it stays a personal tool, the org name does not over-promise. Naming the umbrella something deliberately silly is a way of refusing to scope-lock any single repo into being "the company." Each child lane stays free to grow into its own thing or quietly die without dragging the brand down.

The other read: "cash for clankers" describes the actual operating loop — agents build, Shane reviews and ships, money flows back. The name is honest about who is doing the work and who collects.

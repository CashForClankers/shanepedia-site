OpenCluck — Chicken Coop IoT Monitor

OpenCluck is Shane's ESP32-based IoT sensor system for monitoring a chicken coop. It watches air quality, temperature, and humidity to catch dangerous conditions before they harm the flock, and it lays the groundwork for tracking egg production over time.

Why it exists

Shane keeps 8 egg-laying hens on borrowed farmland — see The Chickens for the flock itself. Coop conditions — ammonia buildup, excessive heat or cold, high humidity — are silent threats to bird health. A backyard flock on borrowed land is low-margin and can't absorb losses from preventable die-offs. OpenCluck is the monitoring layer that turns a manual daily check into an automated alert system, freeing Shane from being physically present to catch problems.

The name riffs on "OpenClaw" — it's the same philosophy (open hardware + agent-friendly interfaces) applied to chickens instead of compute.

Hardware plan (BOM)

| Component | Purpose | |---|---| | ESP32-CAM + MB board | Main microcontroller + future egg-count camera | | MQ-135 gas sensor | Ammonia and air quality detection | | AHT20 breakout | Temperature and humidity | | Waterproof IP65 project box | Enclosure — protects electronics in the wet coop environment |

The ESP32-CAM is the core chip. The MB (motherboard) carrier provides USB programming convenience and regulated power. Starting with MQ-135 + AHT20 covers the highest-priority health signals; the onboard camera is the Phase 2 path for egg-count computer vision.

What it monitors

Phase 1 (current target):

  • Ammonia level (MQ-135) — alert threshold ~25 ppm; chronic exposure above that harms respiratory health
  • Temperature — alert on extremes (below ~35°F or above ~85°F)
  • Relative humidity — healthy range 50–70%; high humidity encourages respiratory disease and mold in feed

Phase 2 (future):

  • Egg count via ESP32-CAM frame analysis or simple counter at nesting box entrance
  • Long-term production curves by season correlated against weather data

Alert mechanism

Alerts will fire to Telegram — the same channel Shane already operates for OpenClaw. This fits the existing stack: no new notification surface to manage, alerts land in the same chat where other automated signals arrive.

Threshold logic runs on the ESP32 itself (edge compute). The device posts to a lightweight endpoint (could be a simple HTTPS webhook, Home Assistant, or a minimal VPS script) that forwards to the Telegram bot. No cloud dependency required for basic alerting.

Current status

Research and build phase. No hardware deployed yet. The BOM is settled. Key open questions before a first deployment:

  • Power: solar + 18650 battery pack vs. running a wire from the farmland structure
  • Connectivity: WiFi range from the house to the coop; may need a WiFi extender or LTE backup
  • Calibration: MQ-135 requires warm-up and baseline calibration in ambient air before readings are reliable
  • Mount point: sensor placement matters — ammonia is heavier than air and pools near the floor, where hens sleep

What success looks like

Phase 1: Receives an alert within 5 minutes of ammonia hitting a set threshold. No false positives from normal coop activity (droppings, ventilation cycles). Data logged to CSV or SQLite for review.

Phase 2: Weekly egg count trend visible without physically counting nests every day. Seasonal production curves documented over 6–12 months.

Long-term: A durable open-source firmware project that could apply to any backyard flock. The ESP32 skill set developed here directly transfers to the vending machine terminal project (MQ-135 sensing, edge compute, webhook integrations).

Related context

The hardware skills overlap directly with Vending Machine Terminal Technology — Lightning + Credit Card — ESP32 development, enclosure work, and webhook-based alerting are shared across both projects. The operational context for the flock itself lives in Backyard Chickens — Oregon Keeper Notes.

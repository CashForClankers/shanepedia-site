Vending Machine Terminal Technology — Lightning + Credit Card

How to build or retrofit a vending machine to accept Bitcoin Lightning and credit card payments, display QR codes, and trigger dispensing on payment confirmation.

Recommended first stack

The cleanest path is staged, not perfect on day one:

  1. Start with the easiest live checkout path: card payments plus a Bitcoin-friendly option that can ship fast.
  2. Add a Raspberry Pi / tablet layer that shows Lightning invoices and confirms payment.
  3. Integrate MDB only after checkout and venue placement are proven.

For Shane's current lane, the right bias is "get one machine live" before optimizing for maximum sovereignty.

Settled stack as of 2026-04-18

After current-source review, the recommendation is:

Production recommendation

  • Lightning: BTCPay Server
  • Card: Stripe Terminal
  • Self-service reader: Verifone UX700 if Stripe availability/cooperation is workable
  • Machine control: Qibixx MDB Pi Hat Plus or MDB-USB
  • Host: Raspberry Pi 5 or equivalent small Linux box

Why:

  • BTCPay already supports a web-based PoS app for brick-and-mortar usage and exposes a Greenfield API/webhook path for custom checkout logic.
  • Stripe's UX700 is explicitly positioned for self-service use and Stripe recommends the server-driven integration for it.
  • Stripe Terminal supports offline card storage for supported card payments when connectivity drops.
  • Qibixx now exposes a high-level serial interface and separate VMC / peripheral capabilities on the Plus hardware, reducing custom MDB risk.

Fast fallback if UX700 is too slow to obtain

  • Keep BTCPay Server for Lightning
  • Keep Qibixx for MDB
  • Use a more attended card-reader flow first, then upgrade the card side later

This preserves the core architecture while avoiding getting blocked on self-service reader procurement.

The Core Architecture

[Customer selects product]
        ↓
[Payment terminal shows QR code / tap NFC / card swipe]
        ↓
[Payment confirmed (Lightning instant / card ~2s)]
        ↓
[Raspberry Pi / ESP32 sends MDB dispense command]
        ↓
[Vending machine releases product]

MDB Protocol — The Key to Vending Hardware

MDB (Multi-Drop Bus) is the industry standard protocol for vending machine peripherals. Nearly all modern vending machines have an MDB port. To add a custom payment terminal:

  1. Your device presents itself as an MDB "cashless payment device"
  2. Customer pays via your terminal
  3. Your device tells the VMC (Vending Machine Controller) to vend
  4. VMC releases the product

MDB Adapters (plug-and-play):

  • Qibixx MDB-Pi (~$150–200): Raspberry Pi hat that talks MDB. Easiest path. Qibixx.com
  • ESP32 MDB Cashless (open source): nodestark/mdb-esp32-cashless on GitHub — DIY, cheaper
  • RS232-MDB converters: rs232-mdb.com — bridges MDB to serial for any computer

Payment Terminal Hardware Stack

Option A: Raspberry Pi + BTCPay + Stripe Terminal (Recommended for MVP)

Components: | Part | Cost | Purpose | |---|---|---| | Raspberry Pi 4 (2GB) | ~$45 | Main computer | | 7" touch display | ~$70 | QR code + UI | | Qibixx MDB adapter | ~$150 | Talks to vending machine | | Stripe Terminal M2 reader | ~$59 | Credit card swipe/tap | | Case + power supply | ~$30 | Enclosure | | Total | ~$354 | |

Software stack:

  • BTCPay Server (self-hosted on Pi or VPS) — generates Lightning invoices
  • Custom web UI on Pi (runs locally, shows QR + payment status)
  • Stripe Terminal SDK — handles card payments
  • Python script bridges payment confirmation → MDB dispense command

Flow (Lightning):

  1. Customer taps product on touchscreen
  2. Pi generates Lightning invoice via BTCPay API, displays QR
  3. Customer scans with Lightning wallet (Phoenix, Wallet of Satoshi, etc.)
  4. BTCPay webhook fires → Pi confirms payment → MDB dispense command sent
  5. Machine vends

Flow (Credit card):

  1. Customer taps product
  2. Stripe Terminal prompts card tap/swipe
  3. Stripe confirms → Pi sends MDB dispense

Option B: ESP32 + LNBits (Ultra-Cheap DIY)

Components (~$80 total):

  • ESP32 dev board (~$8)
  • Small TFT display (~$15)
  • MDB-ESP32 cashless firmware (GitHub)
  • LNBits instance (free, self-hosted) for Lightning invoices

No credit card support without adding a card reader, but suitable for a bitcoin-only machine.

Option C: Tablet + Existing VMC Cashless Port

Some newer vending machines have a built-in cashless device port (MDB ready). You can mount a tablet running:

  • BTCPay Server POS app — generates Lightning QR
  • Square POS — handles card, has Cash App (Lightning) integration
  • OpenNode terminal — managed Lightning, simpler setup

No hardware hacking required — just mount tablet and connect to MDB port.

Reference Implementations (Open Source)

Jellybean Vending Machine

  • GitHub: elaineo/Jellybean
  • Raspberry Pi + Lightning node + GPIO pin triggers
  • Works without MDB — uses direct GPIO to control the vend mechanism
  • Good starting point for custom-built smaller machines

Ricardo Reis — Coke Machine + Lightning

  • Hackster.io project
  • Raspberry Pi 3 + 7" display + BTCPay Server + PUSHER for real-time payment notification
  • PHP web server generates invoices, PUSHER webhook confirms, Pi triggers vend
  • Complete writeup with wiring diagrams

CryptoVend Tablet UI (Devpost)

  • devpost.com/software/cryptovend-tablet-ui
  • Tablet UI for Lightning vending machine — polished UX reference

Payment-for-Vending-Machine (GitHub)

  • iZnd/Payment-for-Vending-Machine
  • QR code payment trigger system for existing machines

NFC / Bolt Card Support

Beyond QR codes, Bolt Card lets customers tap an NFC card to pay Lightning instantly — no phone needed, no QR scan. The card holds a Lightning address and deducts from it on tap.

Hardware needed: NFC reader module (~$15, ACR122U or PN532) + Bolt Card NFC server

This is the slickest UX for repeat customers — like an Orca card but for hot sauce.

Connectivity Requirements

The terminal needs internet to confirm Lightning payments (and card payments). Options:

  • WiFi from the food cart pod (negotiate with operator — usually easy)
  • LTE hotspot (reliable backup, ~$20/month)
  • Starlink if you're ambitious and the pod is outdoors

For Lightning: payment confirmation typically arrives in <2 seconds on a good connection.

Build Priority for Hot Sauce Machine

| Phase | What | Why | |---|---|---| | Phase 1 (MVP) | BTCPay + card checkout on an external UI | Validate pricing, placement, and payment demand | | Phase 2 | Add Qibixx MDB integration | Turn successful payment into real unattended vend control | | Phase 3 | Move to self-service card hardware such as UX700 | Cleaner production-grade kiosk flow | | Phase 4 | Add Bolt Card / NFC support | Best repeat-customer Lightning experience |

Kids / family variant

Do not force the adult vending stack onto the first kids experiment.

For a kids sats-learning machine, the simpler recommendation is:

  • Wallet / accounts: LNbits
  • Kid payment object: NTAG216 NFC cards for tiny balances, later Bolt Cards for safer recurring use
  • Machine: token-based toy capsule machine
  • Reason: faster to deploy, lower breakage risk, easier to explain, still teaches "sats buy things"

See Kids Sats Toy Vending.

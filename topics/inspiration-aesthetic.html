Inspiration and aesthetic

This is the reference page for what Shane's eye is actually drawn to and why. It exists so that any agent or collaborator building a Shane-facing surface — a microsite, a dashboard, a Telegram reply, a CLI tool, a slide deck — can ground design choices in a concrete taste profile rather than guessing.

The core preference: things that boot instantly

The single most consistent signal across the Shane Neeley entity, the Shane design and UX taste page, and the public site corpus is a preference for products that load fast, do one thing clearly, and respect the user's attention. "Simple sites that boot instantly" is repeated almost verbatim in multiple sources, and it is not a stylistic flourish — it is a decision-making rule.

The corollary is a strong dislike of:

  • splash screens, intro animations, scroll-jacking
  • generic startup gradients and SaaS-template hero sections
  • overloaded navigation trees that hide the actual content
  • cookie banners and modal stacks
  • copy that promises "platforms" instead of describing outcomes

If a site fails the boot-instantly test, no amount of subsequent good design recovers it.

Reference set: products Shane likely admires

Inferred from the corpus and the explicit "high-signal minimalism" framing:

  • Stripe docs and the Stripe Press site — long the gold standard for typography-first, content-dense, fast technical reading.
  • Linear — fast keyboard-driven app, restrained palette, opinionated motion design that gets out of the way.
  • Vercel and Vercel's docs — fast, dark-mode native, monospace accents in the right places.
  • Lobsters — proof that a community site can be taste-coded with almost no chrome.
  • Hacker News — the canonical "ugly but instant" reference; Shane's preference is more refined but operates on the same boot-time discipline.
  • Pinboard, the original — "antisocial bookmarking" pricing page as a tone reference: direct, confident, no startup voice.
  • Are.na — editorial layout, generous whitespace, thoughtful typography for a knowledge-work surface.
  • Obsidian — the actual IDE for Shanepedia, locally-first, plain-text underneath, theme-able without becoming busy.
  • GitHub's plain HTML rendering — the version of markdown that just works, no preview pane required.

The pattern across all of those: text first, fast first, opinion first.

Inferred from the Shanepedia site itself

Reading scripts/wiki/build_site.py, the actual Shanepedia public site CSS resolves to a specific palette and type stack that should be treated as the canonical visual identity for any Shane-facing build:

Light mode:

  • background #f7f4ee — warm off-white, paper-tinted, not pure white
  • paper #ffffff for surfaces that need to lift off the background
  • ink #201d1a — soft near-black, not #000
  • muted text #635a53 for secondary copy
  • primary link #0b6a6f (deep teal) with hover #084f53
  • visited link #8b4b3e (oxidised brick)
  • accents in a coordinated warm palette: #c2410c (burnt orange), #0f766e (teal), #b7791f (gold), #2f6fb1 (sky), #6d7f38 (olive)
  • borders #b5aba2 and #ddd4cc — soft, never harsh

Dark mode:

  • background #11161d, paper #171d25 — true dark, slightly blue-shifted, not OLED black
  • ink #e8edf3, muted #aeb8c5
  • accent shifts that preserve the same palette identity in low light (orange #ff9b61, teal #54c2b7, gold #e6b15c)

Type stack:

  • body: Inter, system fallback chain
  • headings: Fraunces, with Linux Libertine and Georgia as serif fallbacks
  • mono: JetBrains Mono, with SF Mono and Cascadia Code as fallbacks

The combination — warm paper backgrounds, deep teal links, oxidised secondary accents, Fraunces for headings — is the identity. Anything Shane-facing that drifts into pure white backgrounds, electric-blue links, and Helvetica-only headings is off-brand even if technically clean.

Why minimal-and-fast wins for Shane specifically

Two reasons, both load-bearing:

  1. He runs many lanes in parallel. Slow tools compound: a 1.5-second page load times a hundred page loads is the difference between a working day and a frustrated one. Fast tools are not a luxury; they are the only tools that survive the multi-lane workload.
  2. He thinks in text. The Shanepedia stack — Obsidian, plain markdown, a static site, a CLI agent — is built around text-as-source-of-truth. Visual chrome that hides the text or makes it harder to grep is a real cost, not a stylistic preference.

This is why most "modern startup design" languages do not fit. Glass-morphism, parallax scrolling, oversized hero videos, and animated illustration sets all impose visual weight without earning it for a text-first founder.

The agentic-but-warm tension

The hardest design problem in any Shane-facing interface is the tension between agentic and warm. An agent surface that is purely functional reads as cold and corporate; one that is purely warm reads as a chat toy and burns trust the first time it gets something wrong. The OpenClaw Telegram channel solves this by alternating registers: morning briefings are crisp and structured, the Saturday meme is loose and weird, error messages are direct, the heartbeat acks are short.

The same tension applies to any visual surface. The Shanepedia site resolves it by pairing serif headings (Fraunces — warm, editorial) with monospace accents (JetBrains Mono — technical, precise) on a paper-warm background with deep-teal links. The combination signals "field notebook with engineering discipline" rather than "SaaS dashboard" or "personal blog."

When in doubt: warm typography on warm backgrounds, technical precision in the metadata and the controls, and zero ornamental decoration. See Agent Personality Design for the corresponding voice rule on the agent side.

How to use this page

Anytime an agent or collaborator is building something Shane will see — a new microsite, a generated report, a Telegram surface, a slide, a card on the public site — open this page first. Confirm the palette, confirm the type stack, confirm the boot-time discipline, confirm the warm-but-precise voice. Then build.

A short checklist for any Shane-facing surface:

  • [ ] loads in under 1 second on a cold cache
  • [ ] uses the warm-paper background, not pure white
  • [ ] links use the deep-teal #0b6a6f (or its dark-mode equivalent)
  • [ ] headings use Fraunces or a serif fallback, not the body font
  • [ ] no startup gradients, no hero videos, no scroll-jacking
  • [ ] copy says one specific thing, not a generic value-prop
  • [ ] mobile layout is real, not a shrunken desktop
  • [ ] there is a clear next action, not a wall of equally-weighted options

Stance

Taste is a constraint, not a decoration. The Shanepedia palette and type stack exist because they have been chosen and tested; departing from them should require a real reason, and the default answer to "should this be flashier?" is no. The most distinctive thing about a Shane-facing interface is not what it adds — it is what it refuses to add.

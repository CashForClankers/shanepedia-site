The Shane Test

Most ideas die in the middle. Not bad enough to kill on sight, not good enough to commit to, so they sit in a notes file until they rot. The Shane Test pulls them out of the middle and sorts them into "ship it" or "leave it" before they consume any more attention.

Use it the moment a new idea shows up — yours, an agent's, a friend's pitch over coffee.

The six questions

Ask in order. Stop when a "no" stacks up.

  1. Does it boot instantly? Can the first useful version exist this week, with no platform, no funding round, no team to hire? If the answer is "first we need a staging environment and a Stripe account," you have not found a project — you have found a job application you wrote for yourself.
  2. Can one person run it? Not theoretically. Today. With your hands. If operations require a co-founder, a VA, or a Slack channel, it is not a fit for how you actually work.
  3. Does it support a real human in a real place? A specific operator in Los Cobanos. A specific food cart pod in Gresham. A specific neighbor who would buy eggs. Abstract markets ("small business owners") fail by default. Reward named people over named segments.
  4. Does it teach you something about hardware, agents, or Bitcoin? These are the three lanes you compound in. Work that teaches you none of them is not bad — it is somebody else's edge.
  5. Would it survive you being away for two weeks? A trip to El Salvador, a quiet week with the kids, a stretch where Telegram is silent. If it collapses without your daily attention, it is not a business — it is a hostage situation.
  6. Does the AI do the boring work, or are you the labor? If you are the labor, you have built a job. The whole point of the agent stack is that research, drafting, monitoring, and follow-ups are owned by software. If the human is the bottleneck, the leverage is gone.

Decision rules

  • Six yeses: ship the smallest version this week. Do not write a plan; write the first artifact.
  • Five yeses, one near-no: ship anyway, but name the weak question. That weakness is what the project has to fix to survive.
  • Four or fewer: put it in [[lateral-bets.md]] if it crosses two existing lanes, otherwise drop it. Do not negotiate with the middle.
  • Fails question 5 specifically: automatic kill. Incompatible with how you live.

How this maps to actual decisions

The test was implicit before it was written down.

  • Bitcoin vending machine — passes. Boots with one machine. One person stocks it. Supports a real food cart pod operator. Teaches Lightning, hardware, and circular-economy ops at once. Survives two weeks because the machine is the operator. See [[hot-sauce-vending-machine.md]].
  • OpenCluck hardware — passes. Single ESP32 build, supports the actual flock on actual borrowed land, teaches embedded plus agent-facing webhooks, runs while you sleep. Skills transfer to vending — double pass. See [[../entities/opencluck.md]].
  • A general-purpose AI startup — fails. Does not boot instantly. One person cannot run it. No specific human at the other end. A thousand exist already. See [[anti-roadmap.md]].
  • A complex SaaS with a billing tier — fails. Even if the idea is good, the shape is wrong. Multi-week boot, support load, the human is the labor for years. The same value usually lands as an artifact plus an agent loop.
  • Manual tour booking for El Salvador operators — fails as built, passes when re-shaped. Doing it by hand is exactly what question 6 catches. The same problem passes the moment the agent does WhatsApp triage and you review edge cases — that is [[agentic-business-studio.md]].
  • A scaled vending empire (50+ machines) — fails. Question 5 dies first; question 2 right behind. One to three machines is a passing version of the same idea.
  • OpenClaw gateway — passes. Already running. One person. Supports a real human (you, daily). Survives travel by design.

When to override the test

Almost never. The one case: an idea that fails questions 1 and 2 but is so cleanly a teaching project for a committed lane that the learning is the deliverable. Even then, write the override down, name the lesson you are buying, set a kill date. If the lesson has not landed by then, the test wins.

The Shane Test is not a wall. It is a hallway with the cheap doors removed.

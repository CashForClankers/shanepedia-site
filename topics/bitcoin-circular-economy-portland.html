Bitcoin Circular Economy — Portland / Gresham / Happy Valley

Goal: find businesses in Gresham, Portland, and Happy Valley that accept Bitcoin / Lightning, so Shane can spend sats locally and support a circular bitcoin economy in the area.

April 18 operating direction

This lane is not just a merchant directory project. The working thesis is:

  • Find existing local businesses that already accept Bitcoin or Lightning.
  • Add an owned spend surface, starting with a vending machine that accepts Lightning and cards.
  • Use that machine as a real node in the local circular economy, not just as a gimmick.
  • Back the lane with lightweight field ops: stocking, maintenance, and in-person merchant verification.

The practical goal is to make local bitcoin spending habitual rather than theoretical.

Primary Maps to Query

BTCMap.org (canonical source)

  • URL: https://btcmap.org/map
  • Open-source, community-maintained, powered by OpenStreetMap tags
  • Coinmap.org shut down — BTCMap is now the standard
  • API: https://api.btcmap.org/v2/elements?area=<area_id> — returns merchants by area
  • Filter: payment:bitcoin=yes or payment:lightning=yes on OSM nodes
  • Search tip: zoom to Portland metro and filter by payment type
  • Community page: https://btcmap.org/communities — check if there's a Portland/PNW community

Bitcoin.com Map

  • URL: https://map.bitcoin.com/
  • Broader (includes BCH), but covers Bitcoin Lightning merchants too
  • Good secondary check

BTCAccepted.org

  • URL: https://btcaccepted.org/
  • Directory format, searchable by location

Yelp / Google "Bitcoin accepted"

  • Yelp: Bitcoin in Portland, OR
  • Not authoritative but catches businesses that self-tag

BTCMap API — How to Query Portland Area

# Get area ID for Portland first (search BTCMap communities or use bounding box)
# Then query merchants in that area
curl "https://api.btcmap.org/v2/elements?area=portland" 2>/dev/null | python3 -m json.tool | head -100

# Or use bounding box for Portland/Gresham/Happy Valley metro
# Approx bounding box: lat 45.40–45.60, lon -122.85 to -122.40
curl "https://api.btcmap.org/v2/elements" \
  --data-urlencode "bbox=-122.85,45.40,-122.40,45.60" 2>/dev/null

Spending Categories to Find

Priority order for circular economy impact:

  1. Food & coffee — highest frequency spend, most valuable for habit-building
  2. Local services — barbers, repair shops, local trades
  3. Retail / hardware — everyday purchases
  4. Entertainment — bars, events, music venues
  5. Online-to-local bridges — local businesses that also sell online with BTC

Owned-machine wedge

The fastest way to strengthen a circular economy is not to wait for every merchant to adopt Bitcoin first. It is to own one or two local spend nodes and then use them as:

  • proof that Lightning checkout works in the local market
  • a conversation starter with pod owners and nearby merchants
  • a recurring place to spend sats on something real
  • a testbed for product pricing, signage, and payment UX

Initial candidates:

  • hot sauce vending machine at a food cart pod
  • coffee or canned-drink machine with Lightning-first branding
  • small countertop smart-locker format for low-footprint pilots

The operational layer for actually running a machine in East Portland lives in Gresham Vending Ops — Running a Machine in East Portland: placement, restocking, LTE, weather, jams, and route economics.

Settled direction as of 2026-04-18

After current-source review, the lane should split into two practical tracks:

Track A: real local spend node

Build one adult-facing machine that accepts:

  • Lightning via BTCPay Server
  • card payments via Stripe Terminal
  • MDB vending control via Qibixx

Why this stack won:

  • BTCPay already has a web-based Point of Sale app for physical stores and a headless API/webhook path for custom flows.
  • Stripe now has a self-service reader path through the Verifone UX700, and Stripe explicitly recommends the server-driven integration for it.
  • Qibixx now exposes a higher-level MDB interface instead of forcing full low-level MDB implementation from scratch.

That combination is the best balance of:

  • real self-service hardware
  • open Lightning control
  • low enough engineering risk for a first machine

Track B: family / education node

Build a simpler kids-facing toy machine that teaches:

  • receiving sats
  • sharing sats
  • tapping or scanning to pay
  • the feeling that sats buy a real thing

See Kids Sats Toy Vending.

The point is not just commerce. It is habit formation: sats feel more real when they buy hot sauce, toys, or tiny rewards in everyday life.

Skill: bitcoin-local-map

A skill that:

  1. Queries BTCMap API for Portland metro bounding box
  2. Filters for Lightning-capable merchants (highest priority)
  3. Groups by category (food, retail, services)
  4. Outputs a ranked list with name, address, payment methods, last verified date
  5. Optionally saves new discoveries to Shanepedia inbox

MVP Script (manual query)

# Run this to get current Portland metro bitcoin merchants from BTCMap
python3 - <<'PY'
import urllib.request, json

# Portland metro bounding box
url = "https://api.btcmap.org/v2/elements?limit=100"
try:
    req = urllib.request.urlopen(url, timeout=10)
    data = json.loads(req.read())
    portland_elements = [
        e for e in data
        if isinstance(e.get('osm_json', {}).get('tags', {}), dict)
        and 'name' in e.get('osm_json', {}).get('tags', {})
    ]
    for e in portland_elements[:20]:
        tags = e['osm_json']['tags']
        print(tags.get('name', 'Unknown'), '|', tags.get('addr:city', ''), '|',
              'LN' if tags.get('payment:lightning') == 'yes' else 'BTC-only')
except Exception as ex:
    print('Error:', ex)
PY

How to Get Listed on BTCMap (for the hot sauce vending machine)

Once the vending machine is live:

  1. Add it to OpenStreetMap with tags: payment:bitcoin=yes, payment:lightning=yes, amenity=vending_machine
  2. It will appear on BTCMap automatically within a day or two
  3. Also submit to BTCAccepted.org and bitcoin.com/maps

Circular Economy Notes

  • Spending BTC locally keeps value in the bitcoin network rather than converting back to dollars
  • Even small purchases (coffee, lunch) matter — they prove demand to merchants
  • Lightning payments are instant and ~zero fee — better merchant experience than card
  • If a business doesn't accept BTC yet, asking is the first step — offer to show them BTCPay setup
  • A field-service layer matters: someone still needs to stock machines, fix jams, and verify merchants in person
  • Kids and families are a valid wedge. A toy machine or rewards dispenser can teach Lightning faster than a lecture because the feedback loop is immediate

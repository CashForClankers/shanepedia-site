Operating rituals

This is what an actually-running founder OS looks like in 2026 — not a productivity manifesto, not a pitch deck for the lifestyle. The actual rhythms in Shane's week, sourced from the live OpenClaw cron schedule, the daily memory files, and the wiki maintenance loop.

The point of writing this down is not aspirational. It is so that any future agent (or future Shane) can recover the rhythm if a machine dies, a config gets blown away, or a long trip resets the cadence. Rituals that survive contact with reality belong here. Aspirational rituals that look good in a journal but never actually run do not.

The morning briefing — 7:00 AM Pacific

Every weekday morning at 7:00 AM America/Los_Angeles, the OpenClaw cron job named "Morning Briefing" fires through the Telegram channel. It is a single agent run that pulls the previous day's wiki log, the open loops dashboard, the bitcoin/El Salvador pulse, and any pending decisions from the active lanes, and delivers a short, scannable status to the phone before Shane is fully awake.

Why 7:00 AM and not 6:30 or 8:00: because it has to land before the first cup of coffee, but after the household has started moving. A briefing that arrives during the kid wake-up window gets ignored. A briefing that arrives at the desk gets read. The 30-minute window matters.

The briefing is intentionally short. Long briefings get skimmed; short briefings get acted on.

The heartbeat — every 2 hours, 7:30 AM to 11:00 PM

OpenClaw's main agent runs a heartbeat every two hours during active hours (configured under agents.defaults.heartbeat, scoped to America/Los_Angeles, 07:30–23:00). The heartbeat is not "are you alive" monitoring — it is a lightweight, isolated context check-in that gives the agent a chance to surface anything worth flagging without waiting for Shane to ask.

In practice the heartbeat catches: a long-running task that finished, a Telegram message Shane missed, a cron job that errored, a wiki page that was edited mid-conversation and needs a follow-up commit. Most heartbeats are no-ops. The 1-in-20 that catches a real thing is what justifies the cadence.

The daily memory file — memory/YYYY-MM-DD.md

Each working day Shane (or an agent on his behalf) opens a fresh markdown file in ~/.openclaw/workspace/memory/ named for the date. It is the day's working scratch — what got decided, what got shipped, what blocked, what to revisit. The format is loose on purpose: bullet lists, short sentences, links to wiki pages that got touched.

This file is not a journal. It is the day's commit log for the founder OS. At the end of the day (or first thing the next morning during the briefing) the agent scans the file for anything that should be promoted into the wiki — a durable insight, a new entity, a contact, a pattern — and writes it back as a real page rather than leaving it trapped in a dated note.

The discipline is: nothing important stays only in the dated memory file. Either it gets promoted to the wiki or it does not matter.

The Saturday meme — 10:23 AM Pacific

Every Saturday at 10:23 AM the "Weekly Meme Delivery" cron fires and sends a generated meme to the Telegram channel via the meme-factory skill. The schedule is deliberately a few minutes off the round hour so it does not collide with the morning briefing pattern and so the timing feels human rather than corporate.

This is the single most "soft" ritual on the schedule and probably the most important one. It is the explicit acknowledgement that an always-on AI gateway is allowed to be a little weird and a little warm — see Agent Personality Design. A founder OS that only ever delivers tasks is exhausting; one that throws a meme into the chat once a week is operable for years.

The Sunday weekly reset — 8:00 PM Pacific

Sunday night at 8:00 PM the "Weekly Reset Brief" cron fires. It is a longer, more reflective agent run than the daily briefing. It reads:

  • the past seven days of wiki log entries
  • the open loops dashboard
  • the projects dashboard
  • any cron job error history
  • the heartbeat trail for unanswered flags

…and produces a Sunday-night "what shipped, what stalled, what to focus on next week" message. The cadence matters: a Sunday reset is what turns a stack of days into a week with a shape. Without it, weeks blur into months.

The reset is also when stale wiki pages get triaged. Anything with last_updated older than its own implied freshness contract gets queued for the Monday backlog.

The PinchBench review — Monday 8:45 AM Pacific

Monday morning at 8:45 AM the "Weekly PinchBench + Stack Review" cron fires. PinchBench is the lightweight benchmarking surface for model and skill performance across the OpenClaw agent stack. The Monday review checks: which models hit which fallbacks last week, which skills had unusual error rates, which cron jobs ran longer than their median, and whether any of it warrants a config change.

This is the ritual that keeps the OpenClaw gateway from quietly degrading. Without a weekly stack review, the agent zoo accumulates silent breakage and configuration drift. With it, model swaps and skill updates ride a regular rhythm instead of always being reactive.

The Shanepedia research flywheel — daily, asynchronous

Layered on top of the cron-driven rituals is the asynchronous research flywheel described in Shanepedia research flywheel: ingest from active lanes, run the autoresearch goals, convert the best findings into wiki updates, rebuild index and lint, log it. This loop does not have a fixed clock time because it runs whenever new evidence lands — a Telegram photo, a saved YouTube link, a research session, a trip.

The discipline is the same as the daily memory file: nothing stays in the lane runtime that should live in the parent wiki.

Why these rituals matter

A founder OS without rituals is just a pile of tools. Rituals are what turn the pile into a system that compounds. The OpenClaw cron schedule is essentially a contract Shane has made with future-Shane: the morning briefing will land, the Sunday reset will run, the Saturday meme will arrive, the heartbeat will check in. As long as those keep happening, the rest of the stack — wiki, skills, agents, channels — has a rhythm to attach to.

The corollary is that adding a new ritual is a serious decision. Each one consumes a slot in the weekly attention budget, and a ritual that gets skipped twice in a row stops being a ritual and becomes a guilt trip. Better to run six rituals reliably than to design twelve and run none.

Stance

The right number of rituals is the smallest set that, if you ran them and nothing else, would still produce a coherent founder operation. Everything beyond that is optional. The current set — morning briefing, heartbeat, daily memory file, Saturday meme, Sunday reset, Monday PinchBench review, asynchronous research flywheel — is close to that minimum. Adding more should be hard. Removing one should require evidence.
